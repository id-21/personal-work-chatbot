# Phase 6 — Memory & Context Summaries

**Status:** Complete
**Date:** 2026-03-02

---

## What Was Built

After each scoped conversation, the system automatically checks whether the pursuit's thought log has grown past a threshold. If it has, a rolling context summary is generated by Gemini and stored in `context_summaries`. The next time the pursuit is opened, this summary is injected into the AI's system prompt instead of raw thought logs — preventing context bloat as conversations accumulate.

## How It Works

```
Scoped chat response finishes
  → after() fires asynchronously (non-blocking)
    → maybRegenerateSummary({ pursuitId, pursuitName })
      → getPursuitThoughtsByPursuitId(limit: 100)
      → if count >= 15:
          → generateText({ model: Gemini, prompt: thoughts })
          → upsertContextSummary({ scopeId: pursuitId, scope: "pursuit", summary })

Next time pursuit page loads:
  → getPursuitWithDetail() already returns contextSummary
  → scopedPrompt() injects it as "CONTEXT FROM PREVIOUS SESSIONS"
```

### Threshold

`SUMMARY_THRESHOLD = 15` thoughts. At ~1-2 thoughts per conversation (the AI logs one thought per meaningful exchange), this triggers after 8-15 conversations. Adjust in `lib/ai/summary.ts` if needed.

### Summary prompt

```
You are summarizing the thought log from conversations about a pursuit called "[name]".
[thoughts ordered chronologically]

Generate a 3-6 sentence rolling context summary that captures:
- Key decisions made or insights reached
- Current blockers or constraints discovered
- Active threads or topics being worked on
- Meaningful progress since sessions began

Write in present tense, flowing prose (no bullet points).
```

---

## Key Decisions

- **`after()` not `await`** — summary regeneration runs after the HTTP response is sent. A slow or failing summary never blocks or degrades the chat experience.
- **Silent failure** — the `after()` block catches all errors. Summary failures are logged to the console but never surface to the user.
- **Upsert not append** — `upsertContextSummary` replaces the existing summary each time rather than accumulating multiple summaries. One row per pursuit in `context_summaries`.
- **Thoughts sorted chronologically** for the LLM — the DB query returns newest-first (for `getPursuitWithDetail`'s recent-thoughts display), but `regeneratePursuitSummary` re-sorts oldest-first before building the prompt so the narrative flows naturally.
- **Manual endpoint** (`POST /api/os/summaries`) — lets you force a regeneration at any time for testing without waiting for the threshold.
- **Wiring already done** — `scopedPrompt()` (from Phase 5) already checks `pursuit.contextSummary` and injects it when present. Phase 6 just fills that field.

## How to Test (Phase 6)

### Automatic (after threshold)

1. Have 15+ conversations in a pursuit so `logThought` has logged 15+ thoughts
2. Check `select count(*) from pursuit_thoughts where pursuit_id = '...'`
3. Send one more message → after response, check `select * from context_summaries`
4. Refresh the pursuit page → open chat panel → the AI's first response will show awareness of past sessions

### Manual trigger

```bash
curl -X POST http://localhost:3000/api/os/summaries \
  -H "Content-Type: application/json" \
  -d '{"pursuitId": "<uuid>"}' \
  --cookie "..."
```

Or use the API with a logged-in session. Returns `{ summary: "..." }` or `{ summary: null, message: "No thoughts yet" }`.

### Verify injection

After a summary exists:
1. Open the pursuit → scoped chat panel appears
2. Ask: `"What have we discussed in previous sessions?"`
3. AI will reference the compressed summary from `CONTEXT FROM PREVIOUS SESSIONS` in its system prompt
